## Prioritized remaining work

1. **Access and release safety (highest priority):** define backend identity and repository ownership; protect `PUT /system/settings`, `POST /system/test-ai`, and repository routes. Restrict provider destinations and keep credentials server-side; review GitHub token storage/transport, upstream multipart body limits, and visual-context retention before public exposure.
2. **Screenshot release gates:** the local browser flow is verified with a mock; resolve repository/report authorization and multipart body limits before public exposure. Run a live full-pipeline screenshot case only with a new explicit paid-request budget; SG-AI-22 approval covered interpretation only. Verify OAuth/private import and Docker/worker paths separately.
3. **Multi-provider live verification:** review the [opt-in local implementation](MULTI_AI_INTEGRATION.md), validate actual Baseten vision-capable and Modal reasoning deployments, and authorize bounded live requests before routing real traffic. Account-wide spend controls and destination review remain open; current credits and subsecond claims are unverified.
4. **AI Core accuracy and labels:** use the [SG-AI-10 evidence and proposed SG-AI-11 plan](SG_AI_10_FALSE_POSITIVE_ANALYSIS.md) to reduce false positives without tuning against the holdout. Obtain named human sign-off for [17-case v3](AI_CORE_LABEL_REVIEW_V3.md) and [RealWorld v2](HOLDOUT_HUMAN_SIGNOFF_V2.md), then freeze the holdout with its fixture hash and source manifest.
5. **Coverage and release materials:** decide TS/JS/Go indexing scope, review accessibility and translations with people, and finish demo/submission evidence. Update [AGENTS.md](../AGENTS.md) and broad marketing claims only after verification.
