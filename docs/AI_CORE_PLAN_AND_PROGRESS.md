## Architecture and contracts

The seven-step `AnalysisOrchestrator` still interprets, retrieves, traverses, reasons, reviews, validates, and writes the brief. `HybridRetriever` only selects indexed, repository-scoped context for impact reasoning; `EvidenceValidator` still gates model claims. `CausalImpactVerifier` then separates source-supported and potential effects. REST and MCP report envelopes remain compatible; explanation, trace, and retrieval metadata fields are additive. Indexed relative paths are normalized to forward slashes on Windows so graph links and source labels resolve consistently. SG-AI-19 adds the approved Pillow dependency for upload-time decoding; no database migration or secret was added. Persisted graph edges are computed at indexing time: reindex repositories to receive corrected call and imported-attribute `reads` edges; the analysis cache version was advanced for report changes. The newer main also adds partial TypeScript/JavaScript indexing through a lightweight parser; this does not imply full AST or cross-language call resolution.

**Architecture review, 2026-10-29:** The current orchestrator creates one provider with `get_ai_provider()` and uses it for vision (when an image is supplied), requirement interpretation, impact reasoning, completeness review, and brief generation. `META_AI_PROVIDER`, `META_AI_API_KEY`, `META_AI_BASE_URL`, and `META_AI_MODEL` are process-wide settings. Baseten and Modal names in the provider factory indicate configurable OpenAI-compatible transport, not separate stage assignments. Baseten vision has a mocked HTTP test; Meta Vision has the one-call SG-AI-22 result. Neither a Modal intent latency below 0.5 s nor the proposed provider credit balances has been verified here. Preserve the deterministic retrieval/graph and evidence/causal boundaries if stage routing is added. Require explicit provider capability, destination, credential, request-budget and trace policies before comparing stage combinations on development fixtures; keep the holdout out of routing optimization.

**Access gate:** `PUT /system/settings` changes provider, model, base URL, and key process-wide without a route-level authorization dependency; `POST /system/test-ai` can initiate inference. Restrict these routes and outbound destinations before public exposure. Otherwise a publicly reachable instance could allow unapproved spending or redirection of model requests containing credentials or repository context. This is an architecture risk inferred from the current route and provider code, not a recorded exploit.

The official Meta docs specify the [API base URL](https://dev.meta.ai/docs/api-reference), [Muse Spark 1.3 model](https://dev.meta.ai/docs/models), and [JSON Schema response format](https://dev.meta.ai/docs/structured-output). The adapter follows those formats; an authorized live full-pipeline smoke and three-case evaluation have now passed. Partner providers retain their existing OpenAI-compatible JSON mode. Offline mode remains the code default; the local ignored `.env` selects Meta.

## Reproduce

From the repository root in PowerShell:

```powershell
$env:PYTHONPATH='services/api'
.\.venv\Scripts\python.exe -m pytest services/api/tests/ -v -p no:cacheprovider --basetemp data/pytest-NEW-UNUSED-DIRECTORY --tb=short
.\.venv\Scripts\python.exe scripts/evaluate_ai_core.py --mode offline --dataset services/api/tests/evaluation/ai_core_cases_v2.json --output data/ai_core_evaluation_v2.json
.\.venv\Scripts\python.exe scripts/replay_ai_core.py --input data/ai_core_evaluation_v2.json
```

Pytest replaces its basetemp, so choose a new directory inside the workspace. The JSON output is Git-ignored. A live smoke is intentionally skipped in the normal suite. With an authorized key in the root `.env`, set `RUN_META_LIVE_SMOKE=1` and `ALLOW_PAID_META_SMOKE=1` in the test process, then run only `services/api/tests/test_live_meta_smoke.py` with the same pytest command. The live evaluation is separate: `scripts/evaluate_ai_core.py --mode live --allow-paid-request --output data/ai_core_live_evaluation_sg_ai_07a.json` after fresh approval. Paid runs are opt-in; do not paste credentials into logs or commit them.
